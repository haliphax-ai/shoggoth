# 2026-07-04

## Fixed: One-shot subagent sessions not terminating after task completion

**The Bug:** One-shot subagent sessions spawned by the workflow orchestrator were never marked as "terminated" because the `createDaemonSpawnAdapter` in `workflow-adapters.ts` kicked off a fire-and-forget model turn promise but never called `sessionManager.kill()` in a `.finally()` block.

**Root Cause:** The `DaemonSpawnAdapterDeps.sessionManager` type only required `spawn`, not `kill`. The `spawn()` method set up a `.then()`/`.catch()` chain to record completion in the completion map, but had no cleanup to terminate the session. These sessions stayed "active" forever.

**The Fix:**

1. Widened `DaemonSpawnAdapterDeps.sessionManager` type from `Pick<SessionManager, "spawn">` to `Pick<SessionManager, "spawn" | "kill">`
2. Added `.finally(() => { deps.sessionManager.kill(childId); })` to the turn promise chain in `createDaemonSpawnAdapter`
3. Updated test mocks in `context-level-system-process.test.ts` and `system-context-adoption.test.ts` to include `kill` stubs

**Note:** The `subagent_spawn` control op in `integration-ops.ts` already had correct termination via `terminatePersistentSubagentSession` in its `finally` block. The workflow adapter was the only code path missing this.

**Files changed:**

- `packages/daemon/src/workflow-adapters.ts` — main fix
- `packages/daemon/test/context-level-system-process.test.ts` — test mock update
- `packages/daemon/test/system-context-adoption.test.ts` — test mock update
